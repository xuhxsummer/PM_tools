请帮我开发一个「H5 文件工具箱」前端项目。

## 一、项目定位

这是一个面向移动端浏览器的轻量级文件处理工具箱。

核心特点：

- H5 Web 页面
- 不需要登录
- 不需要注册
- 不需要用户中心
- 不需要后台管理系统
- 不需要数据库
- 暂时不要开发后端
- 尽可能在浏览器本地完成文件处理
- 用户文件原则上不上传服务器
- 强调隐私、安全、即开即用
- 主要适配手机浏览器，同时兼容 PC 浏览器
- UI 风格使用高级、克制的玻璃拟态设计
- 不要做成传统工具网站或廉价蓝紫渐变风格

第一阶段只开发以下 4 个工具：

1. PDF 转 Word
2. Word 转 PDF
3. 图片格式转换
4. ZIP 解压

项目架构需要方便未来继续增加更多工具。

---

# 二、技术栈

优先使用：

- React
- TypeScript
- Vite
- Tailwind CSS
- Lucide React
- Framer Motion

涉及耗时文件处理的能力时：

- 优先使用 Web Worker
- 必要时使用 WebAssembly
- 不要让复杂文件处理阻塞浏览器主线程

代码必须模块化，不要把所有逻辑堆在一个页面或一个文件中。

---

# 三、核心架构要求

不要将当前 4 个工具写死在首页。

设计统一的 Tool Registry / 工具注册机制。

例如每个工具至少包含：

- id
- name
- description
- icon
- category
- acceptedFileTypes
- route
- status
- processor

未来增加新工具时，应尽量做到：

新增一份工具配置 + 对应处理器，即可自动出现在首页。

未来可能增加：

- PDF 合并
- PDF 拆分
- PDF 转图片
- 图片转 PDF
- 图片压缩
- 图片裁剪
- ZIP 压缩
- 7Z 解压
- 二维码生成
- JSON 格式化

所以架构需要具备扩展性。

# 五、玻璃拟态 UI 规范

整体设计参考 Apple 风格的现代玻璃拟态，但不要直接模仿某个具体 Apple 页面。

关键词：

- 高级
- 克制
- 简洁
- 半透明
- 大圆角
- 柔和阴影
- 空间感
- 轻动画
- 强层级
- 不廉价

## 页面背景

使用浅色系渐变背景。

可以增加 2～3 个大型模糊渐变光斑。

光斑可以有非常轻微的漂浮动画。

不要使用：

- 高饱和赛博紫
- 强烈霓虹
- 大面积深蓝
- 过度炫技动画

## Glass Card

工具卡片采用：

- 半透明白色
- backdrop-filter: blur()
- 半透明描边
- 柔和阴影
- 大圆角
- 轻微高光
- 足够留白

建议：

- Border Radius：20～24px
- backdrop blur：20～30px
- 边框约 1px
- 点击时有轻微缩放或下沉反馈

卡片需要有明显可点击感，但不要做得像传统按钮。

# 六、工具详情页统一设计

# 十二、PDF 转 Word

流程：

选择 PDF → 开始转换 → 输出 DOCX → 下载

纯前端 PDF → Word 的实现难度较高。

因此：

优先寻找成熟的浏览器端 / WASM 解决方案。

如果暂时无法稳定实现：

不要伪造转换功能。

可以将该能力抽象成 Processor Interface，并实现明确的「实验性功能」状态。

UI 和整体流程仍然可以先完成。

代码架构必须方便后续替换 PDF → DOCX 转换引擎。

目标输出：

.docx

需要尽可能保留：

- 文本
- 基础段落
- 基础排版

但第一版不要承诺复杂 PDF 可以 100% 还原 Word 排版。

---

# 十三、Word 转 PDF

支持：

.doc
.docx

流程：

选择 Word → 本地转换 → 输出 PDF → 下载

优先使用浏览器端 WASM 方案。

如使用 LibreOffice WASM：

必须将转换逻辑隔离在独立模块 / Worker 中。

不要把具体第三方库 API 和 UI 强耦合。

# 二十一、代码结构建议

建议采用类似：

src/
  components/
  layouts/
  pages/
  tools/
  processors/
  workers/
  hooks/
  utils/
  types/
  config/

其中：

tools/ 负责工具页面和工具定义。
processors/ 负责不同文件处理能力。
workers/ 负责耗时任务。
config/tools.ts 负责工具注册。

例如：

- PDFToWordProcessor
- WordToPDFProcessor
- ImageConverterProcessor
- ZipExtractorProcessor

UI 页面只调用统一 Processor API。

不要让页面直接耦合第三方文件处理库。

---

# 二十二、状态设计

统一定义工具处理状态，例如：

- idle
- file-selected
- processing
- success
- error

所有工具共用统一状态模型。

---

# 二十三、性能要求

手机端文件处理容易造成内存压力。

必须考虑：

- Blob URL 使用后 revoke
- 避免不必要复制大文件
- 及时释放 ArrayBuffer
- Worker 任务结束后合理释放资源
- 图片处理避免创建大量 Bitmap
- 防止连续处理文件导致内存泄漏

上传大文件时需要合理警告。

不要让浏览器直接崩溃。

# 二十六、开发原则

请先理解整体产品结构，再开始开发。

优先级：

1. UI 统一
2. 移动端体验
3. 架构可扩展
4. 本地文件处理
5. 性能
6. 动画

不要为了快速完成而堆大量重复代码。

不要自行增加我没有提出的复杂业务。

如果某个转换能力受浏览器能力限制：

请采用合理的技术降级方案，并在代码中保留清晰扩展接口。

最终目标是：

做出一个看起来像正式产品，而不是 Demo 的 H5 本地文件工具箱。

页面需要具有高级、干净、轻量的 Apple 风玻璃拟态视觉，同时保证实际可操作性和移动端体验。
